TL;DR

Citadel is an organization vault: shared, governed memory for a team and the agents working alongside it. Your commits, coding sessions, docs, and Linear issues flow in without anyone filing anything, and you search them from the CLI or any MCP client.

What makes it different is the boundary. Everything lands in your private Node first. Central, the org's shared memory, only ever holds what a person deliberately promoted, so it stays small enough to trust. Live numbers, releases, and what is coming next live on the status page.

01 · What it is

Memory with a boundary

Most team knowledge tools ask you to file things. Citadel captures the work you were doing anyway, then keeps the personal and the shared strictly apart.

Personal by default

Everything you capture lands in your own Node. No other seat can read it, and no background job moves it out. Sharing is an act, not a setting.

seat scoped

Central is curated

The org's shared memory only holds what a person promoted into it, so it stays worth trusting instead of turning into a dump of everyone's scratch notes.

promotion gated

Agents are first class

Any MCP client, Claude Code, Cursor, or your own agent, searches the same vault under the same seat and the same read isolation as you do.

MCP native

Source linked

02 · How it works

Three moving parts

You install once. After that the interesting part is what you do not have to do.

Capture

It runs without you. A session hook, a GitHub sync, and a Linear mirror feed your Node while you work. Nothing to file, nothing to remember to save.

Search

One question, both memories. citadel search and the MCP tools read your Node and Central together, and tell you which one answered.

Promote

Sharing stays deliberate. When something is worth the whole org knowing, you promote it. Until then it is yours, including from the agents.

03 · Get started

Two commands

Install the CLI, then hand it your seat token. The onboarding wires up the MCP client you already use.

$ pipx install citadel-archive
$ citadel onboard
