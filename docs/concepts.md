# Concepts

The terms Citadel uses precisely. [`CONTEXT.md`](../CONTEXT.md) is the fuller domain language reference; this page is the short version for people evaluating or adopting the system.

## Seats, nodes, and central

A **seat** is one licensed team member. An admin creates the seat before issuing any token, so every write has an owner.

Each seat gets a **node** (`seat:{slug}`), its own space for working memory. Capture hooks and agent writes land here by default.

**Central** (`masumi-network`) is the shared org layer. Content reaches it through scheduled source sync, tagged contributions, and the promotion agent. That gate is the point: a shared layer that mirrors every private note stops being worth reading.

A third dataset, `session-traces`, holds work someone chose to share so others can consult it. Traces are reference-only and do not feed the promotion path.

## What gets captured

Three things run without anyone filing anything.

A **git pre-push hook** snapshots the commits you push: subject, branch, changed files.

A **Claude Code SessionEnd hook** distills what a coding session was about and what came of it.

**Approved capture roots** are directories you have told Citadel it may summarise. It records the repository state, not your file contents.

Alongside those, scheduled syncs pull GitHub organisation activity, repository content, and Linear issues.

## The learning process

Every write passes through the same pipeline before it becomes searchable.

A **security scan** runs first and blocks content matching secret patterns. This is why a query for an access token or a connection string returns nothing: the material was refused at ingest, not filtered at read time.

**Enrichment** is optional and off by default. When enabled, it sends document text to an external model provider to summarise and structure it. Worth knowing before you turn it on.

**Structuring and indexing** chunks the document, embeds it, and writes the graph relationships that the knowledge mesh renders.

## Promotion

Captured work stays in your node until someone promotes it. The promotion agent proposes candidates, a secret scan gates them, and content reaching Central is recorded in the audit trail with its origin.

Promotion is deliberate by design. Automatic mirroring would make Central a dump rather than a curated layer.

## Trust and provenance

Search results carry the source they came from and a marker saying retrieved content is untrusted context. That marker is not decoration. Anything the vault returns was written by a person or generated by a model, and neither is an authority on its own. Check the citation before acting on it.

Shared session traces carry `_citadel.trust: reference-only`, which means someone found them useful enough to share, not that the org endorses them.

## Cognee

Citadel uses [Cognee](https://github.com/topoteretes/cognee) (Apache-2.0) as its knowledge engine for embeddings and graph operations. It is imported as a dependency rather than vendored, so it can be upgraded independently. Storage, access control, sync pipelines, MCP, CLI, and the web interface are Citadel's own.
